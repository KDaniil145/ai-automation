```text

```

`ldd` также обнаружил отсутствующие `libnss3.so`, `libnssutil3.so`, `libasound.so.2`. Штатный установщик Playwright потребовал sudo, недоступный без интерактивной аутентификации.

Для итогового запуска из официального Ubuntu-репозитория скачаны `libnspr4`, `libnss3`, `libasound2t64` и распакованы в **frontend/.cache/browser-libs**. Системные пакеты не устанавливались. Использована команда из frontend:

```bash
LD_LIBRARY_PATH="$PWD/.cache/browser-libs/usr/lib/x86_64-linux-gnu" corepack pnpm test:browser
```

Это локальный игнорируемый кэш ParcelBot, независимый от других проектов. В исходном коде, конфигурации и итоговом запуске нет зависимости от практики 5. На машине с установленными системными зависимостями достаточно обычного `corepack pnpm test:browser`. Штатная установка и fallback описаны в README.

## Диагностика темы и исправление

Через CSSOM браузера проверены подключённые таблицы, порядок регистрации слоёв, селекторы и computed styles body, карточки, заголовка, кнопок, переключателя и поля в обеих темах.

- В index.css подключён **styles.layer.css** Mantine: его правила действительно находятся в слое `mantine`.
- В dev-результате Tailwind сначала регистрирует `theme, base, components, utilities`, затем встречается слой `mantine`. Из-за этого правило `body, :host { color: var(--mantine-color-text); background-color: var(--mantine-color-body) }` выигрывает у body из слоя base ParcelBot.
- До исправления светлый `--text` был `#111827`, а computed color body — `rgb(0, 0, 0)`. Цвет наследовался заголовками и подписью приоритета. Поля и кнопки с собственными правилами уже использовали нужные токены.
- Исправлены только цвет и фон body: вынесены из base в обычное правило приложения с `var(--text)` и `var(--bg)`. Новый порядок слоёв не добавлялся, `!important` не применялся.
- Браузерные проверки после исправления подтверждают цвет body и фон в обеих темах, а также цвет видимого заголовка светлой темы. Ожидания извлекаются из исходных CSS-токенов. Для светлой темы это `#111827` и `#f4f7fb`, для тёмной — `#f3f6fb` и `#090d15`.
- Скриншоты снимаются с `animations: "disabled"`, после проверки итогового состояния темы.

## Исправление цветов переключателей

Проверена фактическая разметка и CSS Mantine Switch. Атрибут `data-checked` остаётся и со значением `"false"`; селектор наличия атрибута заменён на `.priority-switch input:checked + .priority-track`. Для переключателя темы добавлена нейтральная дорожка светлого состояния. Включено — синяя заливка, белый кружок справа; выключено — серая заливка, белый кружок слева. У темы справа соответствует dark, слева — light.

Токен `--switch-off` задаёт `#4b5563` в тёмной теме и `#9ca3af` в светлой. Новые `!important` не добавлялись, подписи и поведение сохранены. Третий браузерный тест проверяет computed color дорожек, белый цвет кружков и их положение относительно центра дорожки, подпись приоритета и возврат темы обратно. Приоритет проходит on/off в каждой теме, тема — dark → light → dark.

## Что проверяют тесты

API: реальные маршруты WF1/WF2, POST/GET, action, JSON и query, числовые ID, регистр категорий, ошибочные структуры ответа, валидация дат, 400/5xx/не-JSON, отсутствие адреса API.

Компоненты: подписи, доступные ошибки, переключатель с клавиатуры, тема, обязательные поля, ограничения названия и веса, loading/empty/success/error, повторный клик и Enter/submit, сохранение ввода при ошибках и повторная попытка.

Список: автоматическая загрузка, отмена и игнорирование устаревших успехов/ошибок, отсутствие старых строк и счётчика при смене даты, пустая дата, сохранение даты/результатов между вкладками, повторное чтение после remount, недоступный localStorage, обновление после сохранения и независимая ошибка обновления списка.

Полный сценарий проверяет расчёт и сохранение через WF1 и последующее отображение именно данных WF2. В компонентном тесте WF2 намеренно возвращает отличающееся название, что исключает ложный успех за счёт локального добавления сохранённого объекта. Браузерный тест проходит сценарий клавиатурой, проверяет видимый фокус, обе темы и перезагрузку. Второй браузерный тест проверяет мобильную ширину 375px, пустой список, ошибку и повтор. Третий проверяет оба переключателя в обеих темах, как описано выше.

Все API-ответы подменены. Vitest заменяет глобальный fetch, Playwright блокирует внешний трафик без мока. Скриншоты используют системный fallback шрифта: внешний Google Fonts также блокируется в тесте.

## Оставшиеся замечания и ограничения

- Ручная production-интеграция подтверждена пользователем, в том числе записями ID 3, 4 и 5. Агент production API не вызывал. Точное время и версия браузера ручного прогона не предоставлены.
- Автоматизация проверена в Chromium; другие браузерные движки в финальном прогоне не проверялись.
- На этой Ubuntu Chromium требует недостающие системные библиотеки. Успешный прогон использует локальный кэш только ParcelBot; инструкции воспроизведения есть в README.
- Figma Make и ZIP представляют исходный макет; текущие согласованные изменения показаны на скриншотах. Google Fonts блокируется в автоматических тестах, поэтому иллюстрации используют системный fallback шрифта.
- Build подтверждает сборку; мок-тесты — поведение клиента с контрактными ответами. Они не подменяют отдельное ручное подтверждение production n8n пользователем.
- При потере ответа сохранения серверная идемпотентность контрактом не гарантируется; клиент не повторяет POST автоматически и предлагает проверить список.

Новых функций и переделок интерфейса для финального ревью не добавлено. Следующий шаг — независимое ревью и отдельное решение пользователя о коммите.
